# Процесс разработки

## Роли

| Роль | Кто | Делает | Не делает |
| --- | --- | --- | --- |
| Техлид | Claude | Документация, план, задачи для Cursor, ревью отчётов и diff, приёмка архитектуры | Не пишет код задач Cursor |
| Разработчик | Cursor | Ровно одна задача: код, данные, тесты, обновление TDD, отчёт | Не выбирает следующую задачу, не расширяет объём |
| Владелец проекта | Пользователь | Решения по дизайну, сборка, проверка в Unreal Editor, ручные действия в Editor, «готово» | Не программирует то, что можно сделать кодом |

## Цикл задачи

```
STATUS (NEXT) → Claude пишет задачу → владелец передаёт её Cursor → Cursor делает и пишет отчёт →
владелец собирает и проверяет в Editor → Claude ревьюит отчёт и diff → «готово» владельца → STATUS → следующая
```

1. Claude пишет задачу по [Task_Template](Task_Template.md) в `Tasks/` и ставит её в NEXT в [STATUS](../STATUS.md).
2. Владелец даёт Cursor промпт: «Выполни задачу Docs/Development/Tasks/TD-NNN_*.md. Перед началом прочитай CLAUDE.md и файлы из раздела «Что прочитать».»
3. Cursor работает в ветке `task/td-nnn-<кратко>`, коммитит, пишет отчёт в `Reports/TD-NNN.md`, пушит ветку.
4. Владелец собирает проект, выполняет «Действия в Editor» и «Ручную проверку» из задачи.
5. Claude читает отчёт и diff, проверяет критерии приёмки. Замечания → fix-задача той же ветки.
6. Принято двумя сторонами (Claude и владелец) → merge в `main`, STATUS обновлён.

## Git

- `main` — только принятые задачи.
- Ветка на задачу: `task/td-nnn-<кратко>`.
- Коммиты: `TD-NNN: <что сделано>`.
- Бинарные ассеты — через Git LFS.
- Не коммитить: `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`, `.vs/`, `*.sln`.

## Правила

- Одна задача за раз. Параллельно — только независимые задачи с явного разрешения Claude.
- Код не пишется, пока GDD и TDD системы не приняты.
- Нашёл проблему вне задачи — записать в отчёт, не чинить.
