Сделать `ATD_LevelGrid` с типами клеток из маршрутов и объёмов, занятостью и отрисовкой сетки.

## Объём работ
- `ETD_CellType`, `ATD_LevelGrid` (размер, клетка из `DA_TD_GameSettings`, мир↔клетка, тип, занятость, Occupy/Release, CanPlace для размера 1×1/2×2 и для дорожных препятствий).
- `ATD_GridVolume` (Blocked, LandingZone).
- `ATD_Route` (сплайн, тип, ширина, имя) — только данные для растеризации.
- Растеризация при BeginPlay и кнопкой в Editor (CallInEditor).
- Отладочная отрисовка сетки цветами типов.
- `UTD_GameSettingsData` с полем размера клетки.
- Automation Test: растеризация и CanPlace по случаям GDD/10.

## Вне объёма
- Движение врагов (TD-004).
- Постройка юнитов (TD-007).

## Файлы
- `Grid/TD_LevelGrid.*`, `Grid/TD_GridVolume.*`, `Grid/TD_Route.*`, `Data/TD_GameSettingsData.*`, тест

## Действия владельца в Editor
1. Создать `DA_TD_GameSettings`.
2. Карта `L_TD_Test_FirstPlayable`: плоскость, `ATD_LevelGrid` 32×24, два наземных маршрута с развилкой, объём-препятствие, объём зоны высадки.
3. Нажать «Растеризовать» и проверить отрисовку.

## Критерии приёмки
- [ ] Собирается TDEditor Win64 Development без новых предупреждений.
- [ ] Нет чисел баланса в C++.
- [ ] Нейминг по Coding_Rules.
- [ ] TDD обновлён: TDD/10.
- [ ] Типы клеток совпадают с маршрутами и объёмами.
- [ ] Начала маршрутов — Spawn, концы — Border.
- [ ] CanPlace проходит все случаи из «Крайних случаев» GDD/10.

## Ручная проверка
Включить отладку сетки, сравнить с маршрутами, подвигать сплайн и перерастеризовать.

## Риски
- Точность растеризации на поворотах сплайна.
