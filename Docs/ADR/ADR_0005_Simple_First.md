# ADR-0005 — Simple First, без переусложнения

## Статус
Принято

## Контекст
Опыт GrimProtocol: архитектура «на будущее» и наслоения делали каждую задачу большой. TD — инди-проект с ИИ-разработкой маленькими задачами.

## Решение
Порядок приоритетов: работающая реализация → встроить в цикл → читаемость → оптимизация по замеру.

Запрещено:
- Менеджеры менеджеров и «универсальные фреймворки».
- Subsystem без ADR (исключение — `UTD_CampaignSubsystem`, ADR-0008).
- Наследование глубже 3 уровней от `AActor`.
- Абстракции «если когда-нибудь понадобится».
- Файлы больше ~1000 строк.

Разрешено: тонкие акторы + компоненты по поведению, DataAsset, интерфейсы там, где нужен общий контракт.

## Последствия
Простой код, маленькие задачи. Возможный рефакторинг при росте — дешевле, чем абстракции заранее.
